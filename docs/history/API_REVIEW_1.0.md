# 1.0 前的 API 审查

> 已归档：结论已在 0.6.0 中实施，见 [CHANGELOG](../../CHANGELOG.md) 和 [MIGRATION-0.6.md](../MIGRATION-0.6.md)。

状态：A1–A4 已采纳，在 0.6.0 中实施；其余条目维持现状。1.0 冻结公开 API（ROADMAP §4 M3），之后只能加、不能改。本文列出冻结前值得改的地方，每条给出建议和代价。审查范围是 `@hold-baby/bucket-db@0.5.0` 的全部导出、CLI、连接串和存储格式。

## 1. 需要决定的改动

| # | 现状 | 建议 | 代价 / 理由 |
|---|---|---|---|
| A1 | `Collection` 是可 `new` 的导出类，构造参数 `(adapter, dbPath, name, options)` 和 `db.collection(name)` 重复 | **只导出类型**（`export type { Collection }`），集合只能通过 `db.collection()` 获取 | 破坏性，但文档里推荐的一直是 `db.collection()`；公开面少一个构造签名和 `CollectionOptions` |
| A2 | 返回的文档类型是 `T`，`_etag` 是可选字段，调用方读它要写 `!` | 返回 `Stored<T> = T & { _etag: string }`；`_createdAt` / `_updatedAt` 仍可选（手工放进 `docs/` 的文件可能没有） | 只改类型。`_etag` 每次都有值，类型应如实反映 |
| A3 | `QueryOptions.sort` 是 `Record<string, 1 \| -1>`，字段名不做类型检查 | 改为 `QueryOptions<T>`，`sort` 的键限定为 `keyof T` 加系统字段 | 只改类型，泛型参数有默认值，现有代码不受影响 |
| A4 | `engines.node` 是 `>=20`，CI 测 Node 20 / 22 | **改为 `>=22`**，CI 测 22 / 24 | Node 20 已于 2026-04-30 停止维护（nodejs/Release schedule） |
| A5 | 缺少凭证、适配器选项非法时抛 `ValidationError` | 保持不变 | 都属于调用方输入问题；单独加一个 `ConfigurationError` 收益不大 |
| A6 | `put` 会重置 `_createdAt`（不读旧文档） | 保持不变 | 保留原值要先读一次，就不再是单次请求和原子操作；ROADMAP 已有此决定，冻结前再确认一次 |
| A7 | `find` 一次返回整个数组，没有游标分页 | 1.0 保持不变；以后需要时新增 `iterate()`，属于可加不可改的功能 | 包络内最多 1 万条，一次返回可以接受 |
| A8 | 适配器契约里 `remote?: boolean` 控制是否用快照 | 保持不变 | 名字说的是“读取要走网络往返”，与它的作用一致 |
| A9 | CLI 没有 `insert` / `update` 命令 | 1.0 不加；以后加是兼容变更 | 用 `put` 已能完成 CI 场景的写入 |

## 2. 冻结范围（1.0 之后只加不改）

- `index.ts` 的全部导出（经上表调整后）。
- 错误类层次与 `StorageError.kind` 的四个取值。
- 适配器契约：`get` / `put` / `delete` / `list`、`capabilities`、`remote`。自定义后端依赖它。
- CLI 的命令、参数、输出格式（每行一个 JSON 值）和退出码（0 / 1 / 2）。
- 连接串的 scheme 和查询参数，以及“URL 中不得包含凭证”这条规则。
- 存储格式（`docs/STORAGE-FORMAT.md`）。兼容策略：小版本不改布局；快照格式变更时换用新的带版本号的 key（`_snapshot.v2.json`），不需要迁移。

## 3. 评价第 4 节 P0/P1 的去向（1.0 出口标准）

| 条目 | 状态 |
|---|---|
| 4.1 首次写分片覆盖、4.2 读失败当作空分片、4.3 WAL | 已消除：0.4 起没有索引和 WAL |
| 4.4 OSS 条件写非原子 | 已声明：能力声明为 `none`，带 etag 的 update 抛 `UnsupportedError`；仅当不存在时创建依赖 `forbid-overwrite`，在版本化 bucket 上无效（写进保证表，`doctor` 能检测） |
| 4.5 错误吞没与类型 | 已关闭：`findById` 只对 NotFound 返回 null，并有错误分类 |
| 4.6 重试死代码 | 已关闭：内置客户端，故障注入测试覆盖 |
| 4.7 请求数与规模 | 已关闭：快照、基准，以及包络警告 |
| 4.8 `shardCount`、4.9 双真相 | 已消除 |
| 4.10 查询缓存 | 已删除 |
| 4.11 凭证模型 | 已关闭：支持环境变量、session token、回调；不内置完整凭证链（明确不做） |
| 4.12 查询语义 | 0.5 已定稿 |
| 4.13 路径改写 | 已关闭：非法名字直接拒绝 |

结论：P0/P1 都已关闭或写进了限制。
