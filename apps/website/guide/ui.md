# 查询界面

`bucket-db ui` 在浏览器中打开一个页面，用来查看数据库：它的集合、一张可以过滤、排序和翻页的文档表格，以及每个文档的 JSON。它面向持有凭证的开发者，在自己的机器上使用。它不会创建、修改或删除文档。

```bash
export BUCKET_DB_URL='s3://my-bucket/ci-data?region=us-east-1'   # 凭证来自 AWS_* / OSS_*，与其他命令相同
npx @hold-baby/bucket-db ui
# bucket-db ui: http://127.0.0.1:7340/?token=…
```

![bucket-db ui 查询界面](/ui.webp)

命令会打印地址，用默认浏览器打开它，并一直运行到你按下 Ctrl+C。它是 `bucket-db` 命令行工具的一部分（0.7.0 及以后，Node.js >= 22 或 Bun），不需要安装其他东西。

英文参考：[docs/UI.md](https://github.com/holdbaby5483/bucket-db/blob/main/docs/UI.md)。

| 选项 | 默认值 | |
|---|---|---|
| `--url <url>` | `BUCKET_DB_URL` | 与其他命令相同的[连接 URL](./cli#连接) |
| `--port <n>` | `7340` | `0` 表示选择一个空闲端口。端口被占用时命令失败并说明原因 |
| `--no-open` | 打开浏览器 | 只打印地址 |

没有 `--host`：页面只在 `127.0.0.1` 上提供。

## 页面

- **集合**：在左侧，带各自的文档数。在列表下方的输入框中输入名字可以直接打开一个集合；列表还在加载时可以这样做，还没有文档的集合也可以这样打开。
- **过滤条件**：与 `bucket-db find` 和 `collection.find()` 相同的 JSON，例如 `{"ok":true,"ms":{"$lt":2000}}`。留空表示所有文档。过滤条件不合法时显示库给出的错误，并且不从存储读取任何内容。每个集合最近的 20 个过滤条件保存在浏览器中。
- **表格**：每个文档一行，每页 50 行。列是当前页文档的顶层字段：`id` 在最前，`_createdAt` 和 `_updatedAt` 在最后（以本地时间的简短形式显示；悬停可看到存储的值）。嵌套的值显示为一行 JSON。点击列头按升序排序，再点一次为降序，第三次回到默认顺序（`_createdAt`，然后 `id`）。
- **文档**：点击一行可查看整个文档（含 `_etag`），并可复制。
- **状态栏**：有多少个文档匹配、查询用了多长时间、数据是什么时候读取的。
- 地址栏保存当前视图（集合、过滤条件、排序、页码、选中的文档），因此刷新页面、后退按钮和粘贴的链接都能回到这个视图。
- 跟随系统的浅色或深色主题；按浏览器语言显示英文或中文。

## 它读取什么，何时读取

一次查询就是一次 `collection.find(filter, { sort })`。它的成本与 `find` 相同：在 S3 / OSS 上是对集合的 LIST 加上快照，在 Memory 和 FileSystem 上是读取每个文档（[成本模型](./guarantees#限制)）。**最近一次**查询的结果保存在服务器的内存中，因此翻到下一页或选中一个文档不会读取任何内容。换一个集合、过滤条件或排序，或点击**刷新**，会重新查询。状态栏始终显示数据是什么时候读取的。

BucketDB 数据库中没有任何地方记录**集合**，所以集合列表来自列举数据库前缀下的每个 key，并统计其中形如 `<collection>/docs/<id>.json` 的 key。只列举 key，不读取任何文档。每 1,000 个 key 是一次 LIST 请求，逐个依次发出，所以在大型数据库上需要一些时间；列表会边扫描边填充。发出 100 次请求（100,000 个 key）之后，扫描会暂停并询问是否继续。这一点对没有前缀的 URL（`s3://my-bucket`）影响最大，这时扫描覆盖整个 bucket。

## 它不修改文档，但查询可能写入快照

页面能发出的请求中，没有一个会创建、修改或删除文档：服务器只响应 `GET`，它的端点都不写入文档。

不过在 S3 和 OSS 上，界面的查询就是普通的 `find` 调用，而当需要单独读取的文档超过 16 个时，`find` 会重写集合的查询快照（`_snapshot.v1.json`）。这是一次对 bucket 的写入，与其他所有客户端所做的写入相同；它从不改变文档。要保证完全没有写入，请用只读凭证运行查询界面：快照写入会失败，表格下方出现一条警告，查询照常可用。

## 安全

这个进程持有你的存储凭证，并通过 HTTP 返回你的数据，所以它只接受来自它自己启动的那个浏览器会话的请求：

- 它只监听 `127.0.0.1`，不监听其他地址。
- 打印的地址带有一个随机令牌，每次启动都不同。第一次访问时用它换取一个 `HttpOnly`、`SameSite=Strict` 的 cookie；其他每个请求都需要这个 cookie。没有时返回 403。
- `Host` 请求头必须是 `127.0.0.1:<port>` 或 `localhost:<port>`。这可以阻止 DNS 重绑定，即某个网页以自己的域名访问本地服务器。
- 带有 `Origin` 请求头且不是服务器自身来源的请求会被拒绝，并且从不发送任何 CORS 响应头。
- 只响应 `GET`。
- 页面不从网络加载任何内容，在只允许自身脚本的 Content-Security-Policy 下运行，并且把文档内容作为文本插入，从不作为 HTML。

页面顶部显示的连接 URL 不可能包含凭证：BucketDB 拒绝这样的 URL。

不要把它放在反向代理或隧道后面。它没有账号，除了“启动它的那个人”之外没有任何访问控制。

## 不包含的功能

创建、编辑和删除文档（请使用库或 `bucket-db put` / `delete`）；导出（`bucket-db export`）；图表和聚合；库的过滤条件之外的查询语法。

## 兼容性

从 1.0 起，命令名 `ui` 及其选项受[兼容策略](./compatibility)保护。页面的外观和它背后的 HTTP 端点不受保护：它们只为这个页面而存在，可能在任何版本中变化。
